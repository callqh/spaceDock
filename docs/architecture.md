# SpaceDock 架构

2026-11-16，按当前候选实现整理；尚未替换安装版。历史方案与取舍见 [DECISION.md](../DECISION.md)，实际验证范围见 [verification.md](verification.md)。

## 模块

| 模块 | 职责 |
|---|---|
| SpaceDockCore | 纯按键状态机、配置校验与原子保存、异步请求代次。 |
| KeyboardMonitor | 独立 run loop 上的键盘 event tap，识别组合键后在主线程调用协调器；不保存输入内容。 |
| AppModel | 权限、暂停、排除应用、睡眠、启动/隐藏、窗口搬移流程与错误提示。 |
| SettingsView / AppDelegate | SwiftUI 设置、AppKit 菜单栏和窗口，原生材质与系统控件。 |
| SpaceDockWindowBridge | 查询普通桌面与主窗口归属、搬移并读回确认、检查主窗口可见性。 |
| DockAssignment | 开启当前桌面唤起时，只读检查分配；必要时通过目标应用的 Dock 菜单设为“无”。 |

## 按键与配置

默认按住空格 200ms 后按绑定键触发，每次空格按住只触发一次。短按与快速打字补发空格；修饰键组合透传。单独长按空格在松开时补发重复事件，上限 64 后转透传。前台上下文变化会丢弃待补发的候选空格，避免输入到另一个应用。

配置位于用户 Application Support/SpaceDock/config.json，schemaVersion 为 1。绑定保存 id、名称、bundle identifier、路径、物理键位及 summonHere。旧 autoHide/predictiveHide 字段由 Codable 忽略，保存时不再写出。损坏配置保留原文件并停止监听/保存，支持用户主动备份重置。

## 两种唤起路径

- 普通唤起：使用 NSWorkspace.openApplication(activates=true) 显示或重新打开窗口。跨桌面切换依赖系统“切换应用时切换到包含其窗口的空间”，本机已由用户授权开启。不包含额外的私有窗口焦点事件。
- 当前桌面唤起：仅操作已经运行且有可靠 AX 标准窗口的应用。按 main/focused 优先识别；缺少主/焦点语义时，仅接受唯一标准窗口。结合 CG 所属进程/层级与 Space 验证。请求内保留同一 AX 引用、窗口 ID 和运行进程对象，搬移、恢复隐藏/最小化、窗口级激活与最终焦点校验均使用该身份。没有跨请求窗口缓存，不回退到最大绘图窗口。用户已选择优先打开应用：启动前进程不存在或搬移前无法识别可靠窗口时，由 AppModel 使用普通打开，可能切换桌面；取消、权限丢失以及搬移/聚焦失败不触发这一回退。桥接返回明确结果类型，不用错误文案判断。

当前桌面模式只有目标窗口已在当前桌面、可见且获得焦点时，重复快捷键才隐藏应用。普通模式保留前台可见窗口的隐藏切换，无窗口时仍使用系统 reopen。当前桌面模式的未启动/关闭后重建交给系统普通打开，不再保证此时留在当前桌面；空 AX 列表仍不被解释为确定已关闭。桌面切换不触发自动隐藏，也没有触控板预测进程。

搬移使用动态查找的私有 SkyLight 接口，未修改 SIP，也不注入 Dock。全屏源/目标不支持；多显示器边界尚未验收。搬移后先读回归属，再恢复并聚焦；最终同时校验身份、桌面、隐藏/最小化、可见和焦点。只进行有界状态查询，不重复发送激活或延迟 Raise。状态确认不是系统层面的原子操作，无法保证第三方应用不会在完成后自行改变状态。

## 并发与生命周期

快捷键、配置更改及生命周期处理在主线程协调。LaunchLedger 以全局最新请求和桌面 generation 识别旧请求；切换到非目标应用、配置保存、暂停、权限丢失、睡眠和按键录入使请求失效。当前桌面唤起在提交及完成搬移时检查请求和桌面，仅在搬移前缺少可靠窗口时回退普通打开；搬移或激活失败不回退。已经提交给系统的异步动作不能取消，快速连续操作需实测。

外部 AX 查询在独立串行队列执行，主线程仅提供请求有效性与结果回调。NSRunningApplication 状态随主线程运行循环更新，后台读取不能当作跨步骤原子快照（[Apple 文档](https://developer.apple.com/documentation/appkit/nsrunningapplication)）。设置重开显式取消隐藏、恢复最小化并移动到当前桌面。

键盘适配器以锁保护小型状态机；AppKit 操作不在 event tap 回调中执行。辅助功能权限丢失、安全输入、排除应用、按键录入和暂停会使输入透传。登录启动采用 SMAppService。

## 构建与验证

SwiftPM 工程，无第三方运行时依赖。当前构建脚本使用 macOS 26.5 SDK，以规避本机 CLT 27 缺失 SwiftUI 宏插件的问题；SPACEDOCK_SDK 可覆盖。产物采用 ad-hoc 签名，未公证，本地更新可能需要刷新已有辅助功能授权。

核心测试覆盖按键序列、配置兼容和代次控制；原生应用构建与签名校验独立执行。测试不能代替真实跨桌面验收。已验证结果及仍未覆盖的场景见验证记录。
