# SpaceDock 架构

2026-11-06，按当前实现整理。历史方案与取舍见 [DECISION.md](../DECISION.md)，实际验证范围见 [verification.md](verification.md)。

## 模块

| 模块 | 职责 |
|---|---|
| SpaceDockCore | 纯按键状态机、配置校验与原子保存、异步请求代次。 |
| KeyboardMonitor | 独立 run loop 上的键盘 event tap，识别组合键后在主线程调用协调器；不保存输入内容。 |
| AppModel | 权限、暂停、排除应用、睡眠、启动/隐藏、窗口搬移流程与错误提示。 |
| SettingsView / AppDelegate | SwiftUI 设置、AppKit 菜单栏和窗口，原生材质与系统控件。 |
| SpaceDockWindowBridge | 查询普通桌面与主窗口归属、搬移并读回确认、检查主窗口可见性。 |
| DockAssignment | 开启当前桌面唤起时，只读检查分配；必要时通过目标应用的 Dock 菜单设为“无”。 |

## 按键与配置

默认按住空格 200ms 后按绑定键触发，每次空格按住只触发一次。短按与快速打字补发空格；修饰键组合透传。单独长按空格在松开时补发重复事件，上限 64 后转透传。前台上下文变化会丢弃待补发的候选空格，避免输入到另一个应用。

配置位于用户 Application Support/SpaceDock/config.json，schemaVersion 为 1。绑定保存 id、名称、bundle identifier、路径、物理键位及 summonHere。旧 autoHide/predictiveHide 字段由 Codable 忽略，保存时不再写出。损坏配置保留原文件并停止监听/保存，支持用户主动备份重置。

## 两种唤起路径

- 普通唤起：使用 NSWorkspace.openApplication(activates=true) 显示或重新打开窗口。跨桌面切换依赖系统“切换应用时切换到包含其窗口的空间”，本机已由用户授权开启。不包含额外的私有窗口焦点事件。
- 当前桌面唤起：捕获当前普通桌面，先定位面积最大的普通应用窗口，提交 SkyLight 桥接搬移操作，轮询读回目标归属，再请求重新打开/显示窗口。已有应用不在搬移前收到 reopen 请求，以避免跳回原桌面。

仅当应用已在前台且主窗口可见时，同一快捷键才隐藏整个应用。应用仍在前台但窗口已关闭时，应重新显示窗口。桌面切换不再触发自动隐藏，也没有触控板预测进程。

搬移使用动态查找的私有 SkyLight 接口，未修改 SIP，也不注入 Dock。全屏源/目标不支持；独立窗口不一起搬移，多显示器与冷启动边界未全部实测。接口返回成功不等于窗口已显示，搬移会读回确认，显示后检查可见性。

## 并发与生命周期

快捷键、配置更改及生命周期处理在主线程协调。LaunchLedger 用每应用请求序号与桌面 generation 识别旧请求；配置保存、暂停、权限丢失、睡眠使请求失效。当前桌面唤起在提交及完成搬移时检查请求和桌面，失败不回退为直接激活。已经提交给系统的异步动作不能取消，快速连续操作需实测。

键盘适配器以锁保护小型状态机；AppKit 操作不在 event tap 回调中执行。辅助功能权限丢失、安全输入、排除应用、按键录入和暂停会使输入透传。登录启动采用 SMAppService。

## 构建与验证

SwiftPM 工程，无第三方运行时依赖。当前构建脚本使用 macOS 26.5 SDK，以规避本机 CLT 27 缺失 SwiftUI 宏插件的问题；SPACEDOCK_SDK 可覆盖。产物采用 ad-hoc 签名，未公证，本地更新可能需要刷新已有辅助功能授权。

核心测试覆盖按键序列、配置兼容和代次控制；原生应用构建与签名校验独立执行。测试不能代替真实跨桌面验收。已验证结果及仍未覆盖的场景见验证记录。
